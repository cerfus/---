# Разбор переписки — телеграм-бот

Даёшь боту свою переписку — вставляешь текстом или присылаешь выгрузку —
и он показывает, как на самом деле идёт общение: кто чаще начинает разговор,
как быстро отвечают, где разговор глохнет, что из написанного тобой работает,
а что мешает, и что делать дальше.

А когда писать нечего — попросить готовое следующее сообщение под свою
цель или показать черновик и услышать, как он сядет.

Две половины, и это осознанно:

* **цифры и рамка разговора** считаются обычным питоном — быстро,
  бесплатно и объяснимо: на каждый балл видно, откуда он взялся, а отказ
  в переписке находится и без ключа к модели;
* **разбор сообщений и черновиков** делает Claude — там, где нужен живой
  текст, а не арифметика.

## Программа с окном — без командной строки

Двойной клик по **«Разобрать переписку.bat»** — откроется браузер с
программой. Вставил переписку или выбрал файл, нажал «Разобрать» — вот и
весь путь. Командной строки не видно.

Что стоит знать:

* окно живёт на этом же компьютере, наружу ничего не торчит: сервер слушает
  только `127.0.0.1`, и каждый запрос предъявляет одноразовый ключ из
  адресной строки. Без ключа любой открытый в том же браузере сайт мог бы
  стучаться на наш порт, а каждый разбор стоит денег;
* **закрыл вкладку — программа закрылась.** Запуск идёт без чёрного окна,
  закрывать было бы нечем, поэтому страница стучится раз в десять секунд,
  и через минуту тишины сервер выходит сам. Есть и кнопка «Закрыть
  программу»;
* ключ Claude вводится прямо в окне и ложится в `настройки.json` рядом.
  Без него считаются только цифры — они бесплатные;
* если окно не открылось, смотри `_лог.txt` рядом с программой: раз консоли
  нет, ошибка больше нигде не видна.

Библиотеки нужны только для разбора сообщений через Claude — цифры окно
считает на голой стандартной поставке Python. Поставить их разом:
**«Установить библиотеки.bat»**.

## Быстрый старт без Телеграма

Если окно почему-то не годится, всё то же самое есть в консоли:

```
pip install -r requirements.txt
python report.py --from "C:\Users\Ты\Downloads\ChatExport_2026-09-13\result.json" --me "Иван"
```

Выведет индекс, разбивку по факторам и цифры. Ключ к ИИ для этого не нужен.
Добавь `--ии`, чтобы дописать разбор сообщений (нужен `ANTHROPIC_API_KEY`).

То же самое по вставленному куску — скопируй переписку в файл и запусти:

```
python report.py --вставка кусок.txt --me "Иван"
```

## Два способа дать боту переписку

**Быстрый — вставить текстом.** В Телеграме зажать любое сообщение →
«Выбрать» → отметить нужное → «Копировать» → вставить боту. Длинную
переписку можно слать несколькими сообщениями, бот их соберёт.

Если копирование дало кашу, размечать можно руками — по строке на реплику:

```
я: привет, как дела
она: нормально, а ты
я: тоже
```

Понимаются четыре написания: шапка Telegram Desktop («Аня, [05.09.2026
19:04]»), строка лога с датой и именем, «Имя: текст» без времени и ручная
разметка. При ручной разметке бот не спрашивает, кто из двоих ты, — и так
понятно.

Честное ограничение: во вставленном куске обычно нет дат, поэтому скорость
ответов, тренд и инициатива по нему не считаются. Отчёт прямо называет, чего
ему не хватило, а вес недостающих факторов расходится по остальным. Разбор
самих сообщений от этого не слабеет — ему нужен текст, а не даты.

**Точный — выгрузка.** Даёт всю историю с датами и все восемь факторов.

## Как сделать выгрузку

Нужен **Telegram Desktop** — в телефоне выгрузки нет.

1. Открыть нужный чат.
2. Три точки справа сверху → «Экспорт истории чата».
3. **Снять все галочки с медиа** — нужен только текст.
4. Формат — **JSON**.
5. «Экспортировать».

Получится папка с `result.json`. Боту можно прислать сам файл или всю папку
архивом `.zip`. Читаются также выгрузка в HTML и обычный текстовый лог.

Файл должен быть **до 20 МБ** — это ограничение Bot API на скачивание.
Выгрузка без медиа почти всегда весит пару мегабайт.

## Приватность

В переписке есть второй человек, и согласия он не давал. Поэтому:

* присланный файл разбирается в памяти и **удаляется сразу же**, в `finally`;
* **тексты переписки никуда не сохраняются** — в базе только числа
  (список разрешённых полей — `ЧИСЛА` в `storage.py`, и он закрытый);
* в модель уходит **выборка**, а не весь чат, и **без имён**: они заменяются
  на «Ты» и «Она» вместе с падежными формами;
* после разбора бот забывает и сам чат — в памяти остаётся только
  обезличенная выборка на случай уточняющих вопросов;
* команда `/delete` стирает про человека всё, включая купленные разборы.
  Одно исключение названо прямо в ответе бота: записи о платежах остаются,
  но без привязки к человеку — без них невозможен возврат денег.

Это проверяется тестом: `test_limits.py` пишет отчёт в базу и ищет в её
байтах текст переписки — если найдёт, проверка падает.

## Что это за переписка

Индекс вовлечённости меряет ровно одно — ухаживание: идёт ли она
навстречу. Пока переписка про это, всё честно. Принеси дружескую — и тот
же индекс выдаст «18 из 100, встречного интереса почти не видно» про
подругу, которая просто подруга. Арифметика верна, вывод мимо.

Поэтому до всяких цифр `frame.py` отвечает на вопрос попроще: что здесь
происходит. Шесть ответов, первый сработавший выигрывает:

| Тип | По чему видно |
|---|---|
| **отказ** | узкий список оборотов **в её** словах: «нет, спасибо», «давай останемся друзьями», «не пиши мне», «у меня есть парень» |
| **советчица** | речь про тебя и про кого-то третьего разом («она» вместе с «ты» — в переписке двоих это всегда кто-то ещё), и таких реплик не меньше десятой части её сообщений |
| **заглохло** | две недели тишины, либо тренд вниз и последнее слово за тобой |
| **дружба** | 30+ сообщений в день две недели и дольше, оба отвечают быстрее пяти минут, и про чувства со встречами меньше 2% переписки |
| **общаетесь** | разговор начинают поровну, пишете одинаково подробно, оба отвечают быстрее часа |
| **ухаживание** | всё остальное — то, что бот и так предполагал |

Два последних правила пришли с живой переписки на 5956 сообщений.
Сначала бот объявил её «дружеским общением» на основании 16 реплик про
третьего — это 1% её сообщений, чистый шум: за полгода любые двое
случайно помянут «ей» рядом с «ты» шестнадцать раз. Порог стал долевым.
А когда неверная рамка ушла, открылась пустота: бот сказал «интерес
прохладный, навстречу не идёт» про человека, который отвечает за пять
секунд по полсотни раз в день три месяца подряд. Детектор дружбы у нас
был ровно один — «советчица», и обычной дружбы он не видел.

Условий у дружбы четыре, и нужны все. Темп и скорость поодиночке съели
бы настоящее ухаживание — оно тоже бывает быстрым и частым. Отличает
дружбу именно **отсутствие романтической линии на дистанции**, и
считается она зеркально совету про третью: слово про чувства или встречу
плюс «ты» и без третьего лица. «У неё парень есть» так не засчитается —
это разговор про чужую жизнь, а не про вас двоих.

Считается на голом питоне: без ключа, без сети и без денег. Значит,
работает и на бесплатном тарифе — там, где раньше защиты не было вовсе.

Правила нарочно узкие, той же дисциплины, что счёт вопросов в `metrics.py`.
Приписать человеку отказ, которого не было, хуже, чем не заметить отказ:
в первом случае мы врём, во втором просто молчим. И на каждый найденный
отказ показывается **цитата с датой** — улика, а не приговор: ложное
срабатывание видно сразу.

Там же и оговорка про свежесть: «последнее сообщение было 76 дней назад —
**если выгрузка свежая**». Отличить мёртвую переписку от выгрузки
месячной давности нельзя, и делать вид, что можем, не стоит.

## Как выглядит отчёт

Первым идёт не таблица, а **что видно** — цифры человеческим языком:

```
🟠 44 из 100 — вовлечённость сейчас

Что видно
• она начала 1 разговор из 20 — остальные начинал ты
• смех или эмодзи — 3% её сообщений
• 74% переписки — после полуночи
• 20 разговоров из 37 закончились твоим сообщением
```

Восемь полосок человек не читает: «скорость 15 из 15» рядом с
«инициатива 3 из 20» выглядит кашей. А «она начала 1 разговор из 20» —
это уже мысль, и про то же самое. Полоски никуда не делись, они ниже.

**Куда идёт** — две линии по неделям:

```
Индекс:    ▄▄▅▄▄▄··▅▄▄▅
           30.03 40 → 29.06 54 из 100
Сообщений: █▄▂▁▁▁▁▁▁▁▁▁
           3081 в первую → 180 в последнюю
```

Линии именно две и порознь: шкалы у них разные — сотня баллов и
сообщения в неделю, — а совмещать разные шкалы на одной оси нельзя,
это самый частый способ соврать графиком. Подписаны только концы:
число над каждой точкой не читают. Неделя, где сообщений почти не было,
даёт точку-дыру, а не выдуманный уровень.

**Что должно измениться** — арифметика, а не пророчество:

```
• на тебе обрывается 54% разговоров. Половина баллов — если не больше 20%
• она начала 1 разговор из 20. Половина баллов — с каждого 4-го
```

Норма каждого фактора лежит в `metrics.ФАКТОРЫ`, поэтому «половина
баллов» считается, а не выдумывается.

### Чего в отчёте нет

**Вероятностей исхода.** «12% шанс на отношения» посчитать не из чего:
от «отвечает за пять секунд» до такого числа нет никакого пути, его
можно только выдумать. Весь продукт держится на том, что за каждым
баллом видна арифметика, и одно выдуманное число рядом с настоящими
убивает доверие ко всем остальным. Данных об исходах у нас тоже ноль —
даже «обычно такие переписки затухают» сказать не на чем.

**Вердиктов «стоит / не стоит».** Бот показывает, что видно, вывод
делает человек. В наблюдениях не встречаются слова «стоит», «советую»,
«попробуй» — это проверяется тестом, чтобы правило не размылось при
следующей правке формулировок.

## Что бот не делает

Не даёт приёмов давления, не учит «пропадать для интереса» и не помогает
обходить отказ. Отказ ловится дважды: `frame.py` — по словам, ещё до
обращения к модели, и сама модель — через `стоп_сигнал`. Сработало любое —
бот показывает только это и **не печатает никаких советов**, черновик не
проверяет, и к модели не обращается вовсе (значит, и денег не тратит).
Правило одно на все три интерфейса: бот, консоль и окно.

## «Что написать сейчас»

Кнопка после разбора (и команда `/write`). Бот даёт **готовое
следующее сообщение** под ту цель, которую человек выбрал перед разбором,
— две-три версии, которые можно отправлять как есть, плюс почему именно
так и чего сейчас писать не стоит.

Главное в ней — два тормоза, и оба считаются питоном **до** обращения
к модели.

**Чей ход.** Если последнее слово твоё и она молчит не дольше, чем молчит
обычно, никакого следующего сообщения не существует: бот говорит «подожди»
и **не тратит ни квоту, ни токен**. Порог — сутки, но не меньше трёх её
обычных ответов (`metrics.ПОРОГ_ДОБИВКИ`, `ДОЛЕЙ_ОТ_ЕЁ_МЕДИАНЫ`): если она
и так отвечает через день, сутки молчания ещё ничего не значат. Во вставке
с телефона дат обычно нет — тогда подсказка выдаётся, но с честной
припиской, что «не рано ли» никто не проверял.

**Размер шага.** `metrics.ступень` смотрит на индекс последней трети:
ниже 30 — «одно лёгкое сообщение без просьб и приглашений», 30–55 —
«конкретный вопрос или мягкое предложение», выше — «можно прямо, с местом
и временем». Цель при этом никуда не девается, меняется только размер
следующего шага к ней: звать на свидание там, где она отвечает односложно
раз в сутки, — это ровно та ошибка, которую разбор и должен показывать.
`frame.поправить_ступень` дополнительно прижимает шаг к малому, если это
дружеская переписка или она давно заглохла.

Если выбранная цель к переписке не подходит вовсе — например, «позвать на
свидание» там, где собеседница обсуждает с тобой третьего человека, — бот
говорит это прямо (`Подсказка.цель_не_та`), а не подбирает слова молча
не для того человека.

## Черновик: «как это сядет»

После разбора появляется кнопка **«Проверить черновик»**. Присылаешь то,
что собираешься отправить, — бот говорит, как это прочитается с её
стороны, что может оттолкнуть, и даёт две-три готовые версии, которые
можно отправить как есть.

Разбор целой переписки делают раз в неделю (и лимит такой же), а черновик —
каждый день. Поэтому у него свой счётчик, а не общий с вопросами: в какой
лимит упираются люди, в тот и имеет смысл продавать.

Имя собеседницы в черновике заменяется на `{имя}` и возвращается уже
в готовые варианты — в той форме, в какой стояло («жду Аню», а не
«жду Аня»). Обычное обезличивание тут не годится: оно вернуло бы
«Привет, Она».

## Запуск на сервере

```
cd chat_coach
cp .env.example .env && nano .env          # BOT_TOKEN и ANTHROPIC_API_KEY
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f
```

Бот работает на long polling: ни домена, ни сертификата не нужно. База
лежит на примонтированном томе и переживает пересборку образа.

Без докера: `pip install -r requirements.txt && python bot.py`.

### Меню команд

Вставлять список в BotFather не нужно: бот ставит меню себе сам при
запуске, из `texts.КОМАНДЫ`. Одно место на фильтры и на меню — разъехаться
им негде, а разъехались они ровно тогда, когда список жил в переписке
с BotFather, а команды в коде.

Имена команд латинские, и это требование Телеграма: строчные латинские
буквы, цифры и подчёркивание, 1-32 символа. Кириллическое имя BotFather
не примет, а без регистрации у команды нет ни меню, ни автодополнения —
для всех, кроме автора, её просто нет. Русские написания остались
синонимами: напечатанная руками `/удалить` работает как `/delete`.

| Команда | Синоним | Что делает |
|---|---|---|
| `/help` | `/помощь` | как выгрузить переписку |
| `/limit` | `/лимит` | сколько осталось |
| `/buy` | `/купить` | докупить разборы |
| `/write` | `/написать` | что написать сейчас |
| `/draft` | `/черновик` | проверить черновик перед отправкой |
| `/delete` | `/удалить` | стереть всё обо мне |

`/refund` в меню нет намеренно: она админская.

## Деньги

Один полный разбор — примерно **6 000 входных и 2 500 выходных токенов**
(в выход входят рассуждения модели).

| Модель | $/1M вход | $/1M выход | За разбор |
|---|---|---|---|
| `claude-opus-5` (по умолчанию) | $5 | $25 | **≈ $0.09** |
| `claude-sonnet-5` | $2 | $10 | ≈ $0.037 |
| `claude-haiku-4-5` | $1 | $5 | ≈ $0.019 |

Сто активных человек по разбору в день на Opus — около **$9 в день**.
Поэтому лимиты включены с первого дня, а не «когда-нибудь потом»:

* бесплатно — **1 разбор в неделю, 3 вопроса, 3 черновика и 3 подсказки
  в день** (`limits.py`). Счётчики раздельные нарочно: в какой лимит
  упираются люди, в тот и имеет смысл продавать;
* сверх бесплатного разборы можно **докупить пакетами** — витрина по
  команде `/buy` или по кнопке из упёршегося в лимит.

Модель и глубина рассуждений меняются переменными `CHAT_COACH_MODEL`
и `CHAT_COACH_EFFORT` — перезапуск, и всё.

## Оплата

Продаём пакеты разборов: **5 / 15 / 40 за 150 / 350 / 800 ⭐**
(`payments.py`). Купленное не сгорает по календарю и лежит на счету, пока
не потратишь. Бесплатный разбор тратится первым — платить за то, что и так
сегодня даром, человек не должен. Ежедневные вопросы, черновики и подсказки
пакет не трогает: стена, в которую упираются, — это один разбор в неделю.

Подписки нет намеренно: разбор целой переписки делают редко, и платить
за месяц ради двух разборов — плохая сделка, которую человек заметит.

### Почему только звёзды, а не обычная платёжка

Так требует Telegram, и формулировка в документации Bot API не оставляет
места для трактовок: бот обязан использовать Telegram Stars для продажи
цифровых товаров и услуг внутри Телеграма — *«regardless of any other web
portals, apps, services or payment providers you may have set up outside
the Telegram ecosystem»*. Причина не в жадности Телеграма, а в правилах
App Store и Play Store, а следствие названо там же: бота **перестают
показывать мобильным пользователям**. Для нас это вся аудитория.

Схема «продать код на сайте, активировать в боте» подпадает под то же
правило — оно написано ровно про такой обход. Поэтому сторонняя платёжка
(Platega и любая другая) появится тогда, когда появится веб-версия, которой
можно торговать вне Телеграма. В базе под это оставлена колонка `provider`:
второй провайдер встанет туда без переделки слоя.

### Возврат

`/refund <номер платежа>` — команда для одного человека, его id в
`CHAT_COACH_ADMIN`. Пусто — команда не работает ни у кого. Порядок внутри
важен: сначала звёзды уходят обратно через `refundStarPayment`, и только
потом снимается начисленное. Наоборот значило бы при сбое у Телеграма
забрать купленное, денег не вернув.

Номер платежа бот показывает человеку сразу после покупки — чтобы было
что назвать, если что-то пошло не так.

### Что стоит проверить перед включением

Курс звезды к деньгам здесь не зашит и не выдуман: сверься с таблицей
Телеграма, сколько из 150 ⭐ дойдёт до тебя. Пакет из пяти разборов стоит
нам около **$0.45** на Opus — если доходит меньше доллара, поднимай цены,
а не надейся.

## Проверка

```
python test_parser.py && python test_metrics.py && python test_frame.py \
  && python test_report.py && python test_limits.py && python test_payments.py \
  && python test_analysis.py && python test_bot.py && python test_app.py
```

Сети и ключей не требуется: вызов модели подменяется заглушкой, а выгрузки
собираются во временных папках — настоящая переписка в репозиторий
не попадает.

Каждый тест печатает «Проверок: N, провалов: M» и возвращает ненулевой код
при провале, так что их можно ставить в CI как есть.

### Что проверяется отдельно

* **вердикт не врёт** — переписка, которая была тёплой, а потом заглохла,
  получает оценку по последней трети, а не по среднему за всё время
  (`случай_вердикт_по_нынешнему`);
* **имена не утекают** в запрос к модели, включая падежи, и при этом
  «английский» не превращается в «Она» (`случай_обезличивание`);
* **стоп-сигнал** отменяет любые советы (`случай_стоп_сигнал`), и отказ
  виден **без ключа и без сети**: в отчёте он стоит раньше индекса, а вердикт
  про интерес после него молчит (`случай_отказ_без_ии`);
* **правила рамки узкие в обе стороны** — «давай останемся друзьями»,
  сказанное им, отказом не считается, «не пиши ей пока» — тоже, а одна
  реплика про третьего человека не переворачивает переписку в дружескую
  (`test_frame.py`);
* **имя из черновика не уходит в модель** и возвращается в готовые варианты
  в нужном падеже (`случай_черновик`, `случай_черновик_падежи`);
* **черновик после отказа не полируется** и модель не зовётся вовсе
  (`случай_черновик_после_отказа`);
* **один платёж зачисляется один раз** — тот же номер платежа дважды
  не удваивает счёт (`случай_повтор_не_зачисляется`). Это не выдуманный
  случай: Телеграм повторяет апдейт, пока бот не ответит;
* **попытка возвращается в тот же карман, откуда взята** — вернуть
  бесплатную вместо купленной значит молча подарить разбор
  (`случай_возврат_туда_же`);
* **возврат денег не уводит остаток в минус**, даже если разборы уже
  потрачены (`случай_возврат_денег`);
* **черновики тратят свой счётчик**, а не вопросный (`случай_черновики_отдельно`);
* **подсказка не перепрыгивает через цифры** — на холодной переписке
  с целью «позвать на свидание» в запрос уходит малая ступень, а не прямая
  (`случай_подсказка_не_перепрыгивает_цель`), и у советчицы шаг прижимается
  к малому (`случай_подсказка_не_перепрыгивает`);
* **пока она не ответила, подсказки нет** — два часа молчания у той, кто
  отвечает за двадцать минут, это ещё не повод писать второй раз
  (`случай_чей_ход`, `случай_ход_не_твой`);
* **архив** не может распаковаться выше своей папки (`случай_архив`);
* **квоты** не протекают при двух запросах подряд и возвращаются, если
  разбор сорвался не по вине человека;
* **индекс устойчив к сдвигу выделения** — у вставленного куска нет дат,
  вся переписка считается одним разговором, и «инициатива» с «обрывами»
  раньше держались на одном наблюдении: кто случайно оказался первым и
  последним в скопированном. Сдвиг на сообщение уводил оценку на
  одиннадцать баллов. Теперь фактор с числом наблюдений меньше
  `МИНИМУМ_НАБЛЮДЕНИЙ` не показывается вовсе
  (`случай_устойчивость_куска`);
* **вклад никогда не больше потолка** — вылезало дважды: в консоли «19 из
  15» (потолок не пересчитывался после перераспределения весов) и в окне
  «13 из 12» (вклад округлял браузер, потолок питон, и на половинках их
  правила расходились). Теперь оба считает `metrics._округлить`, а проверка
  перебирает все 255 сочетаний выпавших факторов
  (`случай_вклад_не_больше_потолка`);
* **окно не пускает чужих** — без ключа и с чужим отказ, в том числе с
  кириллицей в ключе: `compare_digest` не работает со строками не-ASCII и
  роняла обработчик пятисотой вместо отказа (`случай_чужой_ключ`).

## Запуск на Windows

Нужен Python 3.11+ с сайта python.org — при установке отметить галочку
«Add Python to PATH». Дальше достаточно двойного клика по
**«Разобрать переписку.bat»**; `.bat` сам проверит Python и при первом
запуске доставит библиотеки.

Через командную строку, если так удобнее:

```
pip install -r requirements.txt
python report.py --вставка кусок.txt --me "Иван"
```

Вывод в консоль работает как есть. Если перенаправляешь его в файл
(`> отчёт.txt`), Windows берёт кодировку cp1251, в которой нет ни стрелки
«→», ни полоски «█» — без `console.py` печать падала бы с
`UnicodeEncodeError`. Модуль импортируется сам, делать ничего не нужно.

## Что дальше

* Черновик и подсказка в окне — пока они есть только в боте.
* Веб-версия — и вместе с ней сторонняя платёжка: продавать её вне
  Телеграма правило не запрещает.
* Вебхук вместо polling — когда упрёмся в нагрузку.
* Postgres вместо SQLite — когда одной машины станет мало. Схема в
  `storage.py` намеренно скучная, чтобы переезд был дешёвым.
