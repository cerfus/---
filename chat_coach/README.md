# Разбор переписки — телеграм-бот

Даёшь боту свою переписку — вставляешь текстом или присылаешь выгрузку —
и он показывает, как на самом деле идёт общение: кто чаще начинает разговор,
как быстро отвечают, где разговор глохнет, что из написанного тобой работает,
а что мешает, и что делать дальше.

Две половины, и это осознанно:

* **цифры** считаются обычным питоном — быстро, бесплатно и объяснимо:
  на каждый балл видно, откуда он взялся;
* **разбор сообщений** делает Claude — там, где нужен живой текст,
  а не арифметика.

## Быстрый старт без Телеграма

Проще всего посмотреть, что это вообще такое, прямо в консоли:

```
pip install -r requirements.txt
python report.py --from "C:\Users\Ты\Downloads\ChatExport_2026-09-13\result.json" --me "Иван"
```

Выведет индекс, разбивку по факторам и цифры. Ключ к ИИ для этого не нужен.
Добавь `--ии`, чтобы дописать разбор сообщений (нужен `ANTHROPIC_API_KEY`).

То же самое по вставленному куску — скопируй переписку в файл и запусти:

```
python report.py --вставка кусок.txt --me "Иван"
```

## Два способа дать боту переписку

**Быстрый — вставить текстом.** В Телеграме зажать любое сообщение →
«Выбрать» → отметить нужное → «Копировать» → вставить боту. Длинную
переписку можно слать несколькими сообщениями, бот их соберёт.

Если копирование дало кашу, размечать можно руками — по строке на реплику:

```
я: привет, как дела
она: нормально, а ты
я: тоже
```

Понимаются четыре написания: шапка Telegram Desktop («Аня, [05.09.2026
19:04]»), строка лога с датой и именем, «Имя: текст» без времени и ручная
разметка. При ручной разметке бот не спрашивает, кто из двоих ты, — и так
понятно.

Честное ограничение: во вставленном куске обычно нет дат, поэтому скорость
ответов, тренд и инициатива по нему не считаются. Отчёт прямо называет, чего
ему не хватило, а вес недостающих факторов расходится по остальным. Разбор
самих сообщений от этого не слабеет — ему нужен текст, а не даты.

**Точный — выгрузка.** Даёт всю историю с датами и все восемь факторов.

## Как сделать выгрузку

Нужен **Telegram Desktop** — в телефоне выгрузки нет.

1. Открыть нужный чат.
2. Три точки справа сверху → «Экспорт истории чата».
3. **Снять все галочки с медиа** — нужен только текст.
4. Формат — **JSON**.
5. «Экспортировать».

Получится папка с `result.json`. Боту можно прислать сам файл или всю папку
архивом `.zip`. Читаются также выгрузка в HTML и обычный текстовый лог.

Файл должен быть **до 20 МБ** — это ограничение Bot API на скачивание.
Выгрузка без медиа почти всегда весит пару мегабайт.

## Приватность

В переписке есть второй человек, и согласия он не давал. Поэтому:

* присланный файл разбирается в памяти и **удаляется сразу же**, в `finally`;
* **тексты переписки никуда не сохраняются** — в базе только числа
  (список разрешённых полей — `ЧИСЛА` в `storage.py`, и он закрытый);
* в модель уходит **выборка**, а не весь чат, и **без имён**: они заменяются
  на «Ты» и «Она» вместе с падежными формами;
* после разбора бот забывает и сам чат — в памяти остаётся только
  обезличенная выборка на случай уточняющих вопросов;
* команда `/удалить` стирает про человека всё.

Это проверяется тестом: `test_limits.py` пишет отчёт в базу и ищет в её
байтах текст переписки — если найдёт, проверка падает.

## Что бот не делает

Не даёт приёмов давления, не учит «пропадать для интереса» и не помогает
обходить отказ. Если в переписке виден явный отказ или просьба не писать,
модель обязана поставить `стоп_сигнал` — тогда бот показывает только это
и **не печатает никаких советов**. Так надёжнее для всех и заодно избавляет
продукт от жалоб.

## Запуск на сервере

```
cd chat_coach
cp .env.example .env && nano .env          # BOT_TOKEN и ANTHROPIC_API_KEY
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f
```

Бот работает на long polling: ни домена, ни сертификата не нужно. База
лежит на примонтированном томе и переживает пересборку образа.

Без докера: `pip install -r requirements.txt && python bot.py`.

## Деньги

Один полный разбор — примерно **6 000 входных и 2 500 выходных токенов**
(в выход входят рассуждения модели).

| Модель | $/1M вход | $/1M выход | За разбор |
|---|---|---|---|
| `claude-opus-5` (по умолчанию) | $5 | $25 | **≈ $0.09** |
| `claude-sonnet-5` | $2 | $10 | ≈ $0.037 |
| `claude-haiku-4-5` | $1 | $5 | ≈ $0.019 |

Сто активных человек по разбору в день на Opus — около **$9 в день**.
Поэтому лимиты включены с первого дня, а не «когда-нибудь потом»:

* бесплатно — **1 разбор в неделю и 3 вопроса в день** (`limits.py`);
* кнопка «Хочу премиум» пока только записывает нажатие. Это и есть замер
  спроса: `база.спрос_на_премиум()` покажет, сколько людей упёрлось в потолок.
  Оплату (Telegram Stars) подключать имеет смысл, когда это число перестанет
  быть однозначным.

Модель и глубина рассуждений меняются переменными `CHAT_COACH_MODEL`
и `CHAT_COACH_EFFORT` — перезапуск, и всё.

## Что внутри

| Файл | Зачем |
|---|---|
| `parser.py` | Разбор выгрузки: JSON, HTML, текстовый лог, zip |
| `metrics.py` | Метрики и индекс вовлечённости с разбивкой |
| `analysis.py` | Claude: выборка, обезличивание, промпт, разбор |
| `storage.py` | SQLite: люди, квоты, числа (без текстов) |
| `limits.py` | Тарифы и счётчики |
| `bot.py` | aiogram 3: сценарий, кнопки, состояния |
| `report.py` | Консольный отчёт; его же текст шлёт бот |
| `console.py` | Чинит вывод на Windows при перенаправлении в файл |
| `texts.py` | Все формулировки в одном месте |

Разбор выгрузок вырос из `../tg_defects/sort_export.py` — там он обкатан
на настоящих архивах.

## Проверка

```
python test_parser.py && python test_metrics.py && python test_limits.py \
  && python test_analysis.py && python test_bot.py
```

Сети и ключей не требуется: вызов модели подменяется заглушкой, а выгрузки
собираются во временных папках — настоящая переписка в репозиторий
не попадает.

Каждый тест печатает «Проверок: N, провалов: M» и возвращает ненулевой код
при провале, так что их можно ставить в CI как есть.

### Что проверяется отдельно

* **вердикт не врёт** — переписка, которая была тёплой, а потом заглохла,
  получает оценку по последней трети, а не по среднему за всё время
  (`случай_вердикт_по_нынешнему`);
* **имена не утекают** в запрос к модели, включая падежи, и при этом
  «английский» не превращается в «Она» (`случай_обезличивание`);
* **стоп-сигнал** отменяет любые советы (`случай_стоп_сигнал`);
* **архив** не может распаковаться выше своей папки (`случай_архив`);
* **квоты** не протекают при двух запросах подряд и возвращаются, если
  разбор сорвался не по вине человека;
* **индекс устойчив к сдвигу выделения** — у вставленного куска нет дат,
  вся переписка считается одним разговором, и «инициатива» с «обрывами»
  раньше держались на одном наблюдении: кто случайно оказался первым и
  последним в скопированном. Сдвиг на сообщение уводил оценку на
  одиннадцать баллов. Теперь фактор с числом наблюдений меньше
  `МИНИМУМ_НАБЛЮДЕНИЙ` не показывается вовсе
  (`случай_устойчивость_куска`).

## Запуск на Windows

Нужен Python 3.11+ с сайта python.org — при установке отметить галочку
«Add Python to PATH». Дальше в папке `chat_coach`:

```
pip install -r requirements.txt
python report.py --вставка кусок.txt --me "Иван"
```

Вывод в консоль работает как есть. Если перенаправляешь его в файл
(`> отчёт.txt`), Windows берёт кодировку cp1251, в которой нет ни стрелки
«→», ни полоски «█» — без `console.py` печать падала бы с
`UnicodeEncodeError`. Модуль импортируется сам, делать ничего не нужно.

## Что дальше

* Оплата через Telegram Stars — когда спрос будет виден в цифрах.
* Вебхук вместо polling — когда упрёмся в нагрузку.
* Postgres вместо SQLite — когда одной машины станет мало. Схема в
  `storage.py` намеренно скучная, чтобы переезд был дешёвым.
